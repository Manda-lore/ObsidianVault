# Compiler Construction Mod 1
- A compiler is a system program that translates a program written in a source language (c, c++, java) into equivalent program in a target language usually a machine code, assembly code or some intermediate representation
- Other jobs of a compiler
	- Detects errors
	- Checks types
	- Creates intermediate representations
	- Optimizes the program
	- Generates the target code
- Analysis of source program
	- When a compiler receives a source program, it analyses it in various stages. It checks
	- What are individual words / symbols
	- Is the syntax correct
	- Are the variables valid
	- Are the datatypes of variables compatible
	- What does the expression mean
	- What target needs to be generated
## Phases of a Compiler
1. Source program
2. Lexical analysis
3. Syntax analysis
4. Semantic analysis
5. Intermidiate code generation
6. Code optimization
7. Target code generation
8. Target program
- Two key components that work across many phases are
	- Symbol table
	- Error handler
### Lexical Analysis
- Also called as scanner, reads every character of the program and groups characters into meaningful tokens
- Ex: int sum = a + 10;
  Keyword, int
  Indentifier, sum
  Assignment, =
  Indentifier, a
  Operator, +
  Number, 10
  Semicolon, ;
### Syntax Analysis
- Parses handles the syntax analysis, it receives the tokens from lexical analysis and checks whether it follows the grammmer of the programming language
- Example
	- `a + b * c` is valid syntax
	- `a + * b` is invalid syntax
- The parser typically constructs a **parse tree** or a **abstract syntax tree (ast)** to verify the syntax
### Semantic Analysis
- Semantic analysis checks if the program makes sense according to the programming language
- Example
```C
int a;
a = "hello"
```
- The syntax is correct in the above code block but it makes a type error by assigning a string to a int variable
- Semantic analysis looks for errors in logic instead of syntax, like type error, index out of bounds error, null pointer error etc
- Functions of semantic analysis
	- Type checking
	- Checking variable declaration
	- Checking scope
	- Checking function arguments
	- Checking whether indentifiers are used correctly
### Intermidiate code generation
- Intermidiate code generation is also called intermidiate representation (ir)
```C
a = b + c * d;
```
- A possible three-adress representation is:
  ```
  t1 = c * d
  t2 = b + t1
  a = t2
  ```
- An intermidiate representation is useful as it is the starting point of separating source code and target code
### Code optimization
- Optimization tries to improve the generated program
- The objectives of code optimization are
	- Faster execution
	- Smaller code
	- Lower memory usage
	- Better use of registers
- Example
	- `x = 10 * 2` can be simplified to `x = 20`
	- `x = y * 1` can be simplifed to `x = y`
### Code Generation
- The compiler generates code according to the machine in assembly or machine code as necessary
- Example
  ```
  t1 = c * d
  ```
  Might become assembly instructions such as
  ``` asm
  load r1, c
  mul r1, d
  store t1, r1
  ```
# Symbol table
- Symbol table is an important data structure used by alsmost every compiler phase, it stores information about identifiers
- Example
  ```C
  int total;
  float rate;
  ```
- The symbol table may contain
	- Name : type: scope
	- Total : int : global
	- Rate : float : global
- It stores information related to
	- Variable name
	- Data type
	- Scope
	- Memory location
	- Function parameters
	- Return type
# Error Handler
- Errors can happen at different stages
- Lexical error
	- `int x = 10 @ 20` if @ is not a valid operator it returns an error
- Syntax error
	- `int x = ;` the variable is not assigned while using assignment operator, so it returns error
- Semantic error
	- Semantic error looks for type mismatch and logic errors
- A good compiler should detect and report the error with meaningful message
# Grouping of compiler phases
- The compiler phases can be grouped into two phases
	- Frontend and backend or analysis and synthesis
- Frontend / analysis phase
	- Lexical analysis
	- Syntax analysis
	- Semantic analysis
- Backend / synthesis
	- Code representation
	- Code optimization
	- Target code generation

# Bootstrapping
- Bootstrapping is a process of developing a compiler using the same language it compiles
- Example: a c compiler written in c
- Use a existing compiler to compiler initial c compiler, use it to create a improved compiler and so on
- Uses of bootstrapping
	- Develop compiler in their own compiler
	- Improve portability
	- Test compiler implementations
	- Create compilers for new machines
- If an language l has no compiler, we can use bootstrapping to create a compiler and a language
# Data structures used in compiler computing
1. Symbol table : stores information about identifiers
2. Syntax tree : represents the syntactic structure of a program
3. Stack : Used for parsing, expression evaluation, runtime support
4. Queue : used for managing sequences of tokens or intermidiate operations
5. Graph : used for control flow graphs, dependeny analysis, register allocation
6. Hash table : frequently used to implement symbol tables efficiently
# Lexical Analysis
- The first phase of a compiler where the source program is coverted into tokens for easier processing
- The three main terms in lexical analysis are
	- Tokens : defines the category of lexical unit
	- Lexemme : the value of each token
	- Pattern : the order of lexemme
## Role of lexical analyzer
1. Reading source program
2. Grouping characters
3. Producing tokens
4. Removing whitespaces
5. Removing comments
6. Reporting lexical errors
7. Interaction with symbol table
# Input Buffering
- A buffer is a data structure that stores data required for execution usually in ram
- The buffer size depends on the compiler
- Instead of 
  ```
  Disk → one character → scanner
  Disk → one character → scanner
  Disk → one character → scanner
  ```
- The compiler reads a block of characters as
  ```
  Disk
   ↓
  Large block of characters
   ↓
  Input buffer
   ↓
  Lexical analyzer
  ```
- There are 2 input buffering methods
	- Single buffer
	- 2 buffer scheme
- The single buffer may not add all the characters in a line at once, therefore 2 buffer scheme is more popular and used

# Specification of tokens using regular expressions
- Regular expressions are used to describe the pattern of the tokens
- Example : letter(letter | digit)*
## Commonly used regular expressions for tokens

| Operator             | Regular expression               |
| -------------------- | -------------------------------- |
| Identifier           | `letter(letter\|digit)+`         |
| Integer              | `digit+`                         |
| Decimal              | `digit+ "." digit+`              |
| Whitespace           | `(space \| tab \| newline)`      |
| Relational operators | `< \| <= \| > \| >= \| == \| !=` |
## Basic regular expression operators
| Operator | Meaning      |
| -------- | ------------ |
| `        | `            |
| `*`      | Zero or more |
| `+`      | One or more  |
| `?`      | Zero or one  |
| `( )`    | Grouping     |
# Finite Automata
- Regular expressions are converted into finite automation for token recognition
- There are two types of major types
	- DFA
	- NFA
## DFA vs NFA

| DFA                                      | NFA                                      |
| ---------------------------------------- | ---------------------------------------- |
| One transition for each state/input pair | May have multiple transitions            |
| No ε-transitions                         | ε-transitions may exist                  |
| Easier to execute                        | Often easier to construct                |
| Commonly used for fast recognition       | Useful as an intermediate representation |
| Deterministic                            | Nondeterministic                         |
